# V0.8.2 fixed-shell architecture

V0.8.2 readers are generated from two strictly separated layers.

## Fixed product shell

The fixed shell is extracted once from the normalized latest CANVAS HTML. It owns every repeatable product element: document structure, top bar, buttons, mode switch, sidebar, resizers, viewer, settings panel, annotation interface, search interface, typography, spacing, colors, responsive behavior, modal behavior, figure controls, table controls, reference popover, term tooltip, CSS and general JavaScript interaction logic.

The shell contains exactly one neutral exemplar of each repeatable content component: paper section, bilingual paragraph, figure card, table card, reference item, overview question, figure-index section and figure-index button. All CANVAS-specific prose, authors, metadata, figures, tables, references, terminology data and paper-specific runtime arrays are removed. Embedded paper images are not permitted in the frozen shell.

The shell is produced deterministically by `tools/freeze_v082_canvas_shell_v2.py`. It is not generated by an AI model. Its SHA-256 is recorded and propagated into every rendered reader.

## Variable paper data

For each paper, the only permitted generated input is a JSON manifest conforming to `schemas/paper_content_manifest_v082.schema.json`. The manifest may contain paper metadata, overview text, section titles, bilingual paragraph content, source-fragment mappings, figure and table data, captions, figure-study content, terminology definitions and references.

The AI or PDF parser must not emit HTML, CSS, page-layout code, button definitions, colors, interaction scripts or arbitrary DOM fragments. `tools/render_v082_from_frozen_shell.py` deterministically converts the validated manifest into the fixed component exemplars.

## Mandatory gates

`tools/validate_v082_frozen_shell.py` rejects a shell when its fixed DOM, styles or static scripts diverge from the normalized CANVAS master, when more than one exemplar remains, when CANVAS paper content remains, when embedded paper images remain, or when the extracted shell is still content-heavy.

Every rendered paper is then checked by the existing CANVAS shell-lock, component-contract and browser-regression gates. A paper cannot pass by merely looking similar: the fixed shell, component inventory, runtime behavior and content manifest must all pass independently.
