# V0.8.2 CANVAS 模板锁定：差距、实验证据与修复架构

## 结论

当前 `00_V0.8.2_CANVAS...html` 是唯一合格的视觉、交互和阅读结构标准。后续批量文件没有复用该 DOM、CSS 和 JavaScript 外壳，而是重新生成了一套简化页面。因此它们即使通过自身验证，也不具备与 CANVAS 的格式或功能等价性。

新的锁定渲染实验已经证明：同一份标准 CANVAS 文件可以作为不可变母版，论文内容通过结构化 JSON 注入后，输出文件的中和外壳 SHA256 与标准文件完全一致：

`0f5f07b37476b0822699967b7b5275dbe460e4df3d8bc9ca32765f201bf0956a`

冒烟文件通过锁定验证；现有 Maas 和 Valanarasu 批量文件均失败，各发现 35 类外壳差异。

## 标准 CANVAS 实际固定内容

CANVAS 标准文件包含固定顶栏、目录栏、左右拖拽手柄、正文主栏、右侧图栏、快速了解与双语精读两个模式、图表预览、逐段双语块、完整图卡与表卡、图表精读、阅读设置、引用浮窗、术语浮窗、批注、缩放、沉浸模式及导出入口。上述内容全部属于系统外壳，不属于论文内容。

标准文件当前静态规模包括 15 个样式块、固定顶栏控件、目录与中英文切换、左右栏拖拽、右栏查看器、设置面板、批注系统、引用与术语浮窗、图像缩放系统，以及快速了解和双语精读两个固定模式容器。

## 当前批量文件与标准文件的直接差距

现有 Maas 和 Valanarasu 批量文件缺少或替换了以下标准结构：

- 没有标准 `#topbar` 与固定按钮顺序；
- 没有 `#quick-pane` 和 `#bilingual-pane` 两个标准模式容器；
- 没有标准 `#sidebar`、`#toc`、左右拖拽手柄和 `#viewer`；
- 没有标准阅读设置、批注抽屉、术语浮窗、参考文献浮窗和缩放层；
- CSS 样式块与标准文件不同；
- 通用 JavaScript 清单与标准文件不同；
- 页面固定 DOM 顺序不同；
- 使用 `.para-card` 的简化批量壳替代 `.bilingual-unit`、`.figure-card`、`.table-card` 和标准阅读模式。

因此，问题并非某几个按钮遗漏，而是批量生成时整个产品外壳被重新设计。

## 标准文件自身仍存在的数据与代码耦合

CANVAS 文件虽然效果正确，但实现仍把论文数据与通用代码混在一起：

1. 论文标题、作者、期刊和元数据直接写入顶栏与 hero。
2. 快速了解和双语正文直接写入 `#quick-pane` 与 `#bilingual-pane`。
3. 英文来源碎片分散在大量匿名 `application/json` 脚本中。
4. `v080ReviewManifest` 同时保存 CANVAS 专属图表 ID、数量和内容哈希。
5. `canvas-reader-v060-script` 同时包含通用图栏/精读逻辑与 CANVAS 专属 `V6_ASSETS`、`V6_HOTSPOTS`、`V6_STUDY` 数据。
6. `canvas-reader-v061-script` 同时包含通用术语逻辑与 CANVAS 专属 `TERM_DATA`。
7. `canvas-v082-script` 同时包含 V0.8.2 修复逻辑与 CANVAS 专属 `STUDY_IDS`、`ONTOLOGY`。

因此，直接让模型“参考 CANVAS 再写一份 HTML”仍会让模型重写 CSS、DOM、按钮和 JavaScript，并继续产生功能回退。必须把标准文件拆成不可修改的系统外壳和结构化论文数据。

## 已实现的锁定方式

### 不可变外壳

生成器直接读取标准 `00_V0.8.2_CANVAS...html`，保留其固定 DOM、15 个样式块、静态脚本、控件顺序和全部交互容器。生成过程不创建新的页面模板。

### 明确允许变化的内容槽

目前只允许以下区域随论文变化：

- 页面标题；
- `body[data-paper-key]`；
- 顶栏论文名称；
- hero 论文信息；
- `#quick-pane` 内的论文概览；
- `#bilingual-pane` 内的章节、双语段落、图表和参考文献；
- 四个原本与 CANVAS 内容耦合的数据脚本中的论文数据常量；
- 双语段落的来源碎片 JSON。

其他区域一律不可变化。

### 结构化论文数据

模型不再生成 HTML。模型只能输出符合 `schemas/paper_content_manifest_v082.schema.json` 的 JSON，内容包括：

- 论文标题、作者、期刊、DOI 和页数；
- 一页概览；
- 章节顺序；
- 逐段英文、逐段中文和原始来源碎片；
- 引用、术语、图表引用和章节引用；
- 图表资源、完整中英文图注、表格数据和图表精读；
- 完整参考文献。

渲染器 `tools/render_v082_canvas_locked.py` 负责使用固定组件生成 HTML。

### 外壳硬门禁

`tools/validate_v082_canvas_shell_lock.py` 会把论文内容槽中和后比较：

- 全部样式块哈希；
- 静态脚本顺序与哈希；
- 顶栏固定控件顺序；
- 主布局固定节点顺序；
- 目录、拖拽条、右栏、设置、批注、术语、引用和缩放组件；
- 中和后的完整 DOM 外壳 SHA256。

任何一项不同即失败。

## 锁定原则

V0.8.2 后续所有论文必须满足：

- 使用同一个 CANVAS 标准 HTML 作为唯一母版；
- CSS、通用 JavaScript、顶栏按钮顺序、侧栏、拖拽条、右栏、设置面板、批注系统、缩放和图表精读结构不可由模型生成或修改；
- 模型只能输出符合 JSON Schema 的论文数据；
- 生成器负责把结构化数据渲染为 CANVAS 已有组件；
- 文章之间允许变化的只有标题、作者与元数据、概览文本、章节、逐段英文与中文、术语、引用、图表资源、图注和图表解读；
- 任一输出与 CANVAS 的静态外壳指纹不一致即阻断发布；
- 不再允许为不同论文生成独立 CSS、独立页面布局或独立按钮实现。

## 三层架构

1. **不可变外壳**：从标准 CANVAS 提取并锁定 CSS、通用脚本和固定 DOM。
2. **论文内容清单**：PDF 解析、翻译和学术解读只写入结构化 JSON，不产生页面代码。
3. **确定性渲染器**：只使用固定组件模板渲染 JSON；同一数据重复构建必须得到一致结果。

## 发布门禁

发布必须同时通过：

- 静态外壳哈希与 CANVAS 一致；
- 固定控件和 DOM 顺序一致；
- 内容清单符合 Schema；
- PDF 正文、图表、图注和参考文献覆盖完整；
- 英中段落一一对应；
- 浏览器交互回归通过；
- 禁止项扫描通过，包括简化双栏模板、`.para-card` 批量壳、固定 12 段抽取和通用占位图解。

当前锁定渲染器已经解决“不同文章重新生成页面骨架”的问题。后续工作应集中在 PDF 到结构化内容清单的完整生成和真实论文浏览器回归，不再修改页面外壳。
