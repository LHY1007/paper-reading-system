# V0.8.2 CANVAS 模板锁定：差距与修复目标

## 当前事实

当前 `00_V0.8.2_CANVAS...html` 是唯一合格的视觉、交互和阅读结构标准。后续批量文件没有复用该 DOM、CSS 和 JavaScript 外壳，而是重新生成了一套简化页面。因此它们即使通过自身验证，也不具备与 CANVAS 的功能等价性。

CANVAS 标准文件包含固定顶栏、目录栏、左右拖拽手柄、正文主栏、右侧图栏、快速了解与双语精读两个模式、图表预览、逐段双语块、完整图卡与表卡、图表精读、阅读设置、引用浮窗、术语浮窗、批注、缩放、沉浸模式及导出入口。上述内容全部属于系统外壳，不属于论文内容。

## 当前耦合问题

CANVAS 文件虽然效果正确，但其实现仍把论文数据与通用代码混在一起：

1. 论文标题、作者、期刊和元数据直接写入顶栏与 hero。
2. 快速了解和双语正文直接写入 `#quick-pane` 与 `#bilingual-pane`。
3. 英文来源碎片分散在大量匿名 `application/json` 脚本中。
4. `v080ReviewManifest` 同时保存 CANVAS 专属图表 ID、数量和内容哈希。
5. `canvas-reader-v060-script` 同时包含通用图栏/精读逻辑与 CANVAS 专属 `V6_ASSETS`、`V6_HOTSPOTS`、`V6_STUDY` 数据。
6. `canvas-reader-v061-script` 同时包含通用术语逻辑与 CANVAS 专属 `TERM_DATA`。
7. `canvas-v082-script` 同时包含 V0.8.2 修复逻辑与 CANVAS 专属 `STUDY_IDS`、`ONTOLOGY`。

因此，直接让模型“参考 CANVAS 再写一份 HTML”仍然会让模型重写 CSS、DOM、按钮和 JavaScript，并继续产生功能回退。正确方案必须把标准文件拆成不可修改的系统外壳和结构化论文数据。

## 锁定原则

V0.8.2 后续所有论文必须满足：

- 使用同一个 CANVAS 标准 HTML 作为唯一母版；
- CSS、通用 JavaScript、顶栏按钮顺序、侧栏、拖拽条、右栏、设置面板、批注系统、缩放和图表精读结构不可由模型生成或修改；
- 模型只能输出符合 JSON Schema 的论文数据；
- 生成器负责把结构化数据渲染为 CANVAS 已有组件；
- 文章之间允许变化的只有标题、作者与元数据、概览文本、章节、逐段英文与中文、术语、引用、图表资源、图注和图表解读；
- 任一输出与 CANVAS 的静态外壳指纹不一致即阻断发布；
- 不再允许为不同论文生成独立 CSS、独立页面布局或独立按钮实现。

## 三层架构

1. **不可变外壳**：从标准 CANVAS 提取并锁定 CSS、通用脚本和固定 DOM。
2. **论文内容清单**：PDF 解析、翻译和学术解读只写入结构化 JSON，不产生页面代码。
3. **确定性渲染器**：只使用固定组件模板渲染 JSON；同一数据重复构建必须得到一致结果。

## 发布门禁

发布必须同时通过：

- 静态外壳哈希与 CANVAS 一致；
- 固定控件和 DOM 顺序一致；
- 内容清单符合 Schema；
- PDF 正文、图表、图注和参考文献覆盖完整；
- 英中段落一一对应；
- 浏览器交互回归通过；
- 禁止项扫描通过，包括简化双栏模板、`.para-card` 批量壳、固定 12 段抽取和通用占位图解。
