# V0.8.2 顺序批量生成合同

## 执行顺序

批量任务必须先完成 CANVAS 范本，然后按输入清单顺序逐篇处理。不得并行启动多个论文生成任务。只有当前论文同时通过内容完整性检查和独立交互合同二次检查后，才能进入下一篇。

## 每篇论文的阻断门

每篇输出必须逐项满足：双语段落数与来源文件一致；图表资源数与来源一致；所有图片数据完整保留；图卡“右侧”和“精读”动作分离；从正文打开右栏时，有精读数据的图显示精读入口，表格不显示；中英文图解默认展开并独立折叠；图表精读支持横/竖分栏和缩放；划词与绘图批注位于同一入口；批注本初始为空且可定位；术语本体采用最长别名优先和严格字符边界；引用保留可点击上标；旧版快速了解、证据审查、段后便捷注释和预置批注不得复活。

## 二次检查

第一轮检查解析最终 HTML 并核对数量、ID、资源哈希、动作路由、脚本语法和禁止项。第二轮不得复用第一轮布尔结果，而应从交付 HTML 重新读取资源注册表和 DOM，独立模拟右栏及精读路由、表格守卫、图解折叠、术语边界、批注入口和布局切换合同。

## 失败处理

任一论文失败时立即停止后续生成。修复必须写入公共生成器、验证器、提示词合同或本体配置，再从失败论文重新开始；不得只手工修补单个 HTML 后继续。

## 最终交付

最终交付必须包含全部 HTML、总索引、逐篇 QA、功能对照矩阵、顺序与完成度总检及 SHA256 清单。总检只有在所有论文均通过时才能标记 `passed: true`。
