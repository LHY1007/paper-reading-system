# PDF 原生批量生成与发布合同（诊断草案）

## 适用范围

本合同用于从论文 PDF 制作 V0.8/V0.8.1 及后续版本的双语阅读器。它不适用于仅对既有 HTML 施加确定性补丁的版本维护。两种任务必须在构建记录中明确区分：

- **内容生成**：从 PDF 重新建立正文、翻译、图表、图注、参考文献与解释数据；
- **界面迁移**：保留既有内容，仅改变页面结构、交互或样式。

界面迁移通过不得被表述为 PDF 内容生成通过。

## 一、PDF 是内容完整性的唯一上游基准

每篇论文生成前必须运行 PDF 原生结构审计，输出独立清单：

- PDF 页数与文件 SHA256；
- 正文文本块、标题、图表图注、参考文献及重复页眉页脚数量；
- 每个文本块的页码、坐标、原文、块类型与哈希；
- 主图、补充图、主表和补充表的资源清单；
- 可点击引用及对应参考文献编号。

HTML 内部自行报告的段落数、图表数或引用数不得作为正确答案。预期值必须先从 PDF 独立产生，再由 HTML 验证器读取。

## 二、内容层与界面层分离

生成系统必须先输出版本无关的论文内容清单，再由 V0.8 或 V0.8.1 渲染器消费。内容清单至少包含：

```json
{
  "paper": {},
  "sections": [],
  "paragraphs": [
    {
      "id": "p-0001",
      "page": 2,
      "bbox": [0, 0, 0, 0],
      "source_text": "...",
      "source_sha256": "...",
      "translation_zh": "...",
      "citation_ids": [],
      "figure_refs": [],
      "table_refs": []
    }
  ],
  "assets": [],
  "references": []
}
```

V0.8 与 V0.8.1 只能改变渲染和交互，不得各自重新选择“核心段落”或重写论文内容。

## 三、正文段落规则

- 正文必须按论文自然段组织，禁止按固定数量抽取 5、8、12 或 13 个“核心段落”替代全文。
- 跨栏、跨页或行尾断词必须在 PDF 解析阶段合并，禁止把 `com-`、`foundation` 等页面残片作为独立正文。
- 表格单元格、图注、作者单位和参考文献不得进入正文段落序列。
- 英文与中文块必须一一对应并共享同一段落 ID；任何一侧缺失均阻断发布。
- 中文应是对应英文自然段的完整翻译，不得用一句摘要替代多句原文。
- 正文标题和目录必须从章节结构生成，禁止用正文末尾残片生成诸如 `t modeling`、`0 B cells` 的目录项。

## 四、图表规则

每个图表资源必须分别保存：

- 高清原图或表格；
- 英文完整原图注；
- 对应中文完整翻译；
- 正文中引用该资源的段落 ID；
- 图表精读数据；
- 是否允许进入全屏精读模式。

图表精读必须读取原图、完整图注、相关正文和方法段落。自动生成的“图注涉及：蛋白；所有数值以英文为准”等通用占位文本视为缺失内容。

## 五、引用与数字规则

- 引用识别必须在 PDF span 阶段完成，依据字号、基线、位置和上下文判断。
- 普通数字、样本量、年份和小数不得通过 HTML 正则批量转为引用。
- 类似 `14,000` 被解析为 `14,<sup>000</sup>` 时必须阻断发布。
- 正文引用与参考文献列表必须共享稳定 reference ID。

## 六、独立发布门禁

发布必须同时通过以下三类门禁：

### 1. PDF 内容覆盖门禁

- HTML 双语段落数不得低于 PDF 原生预期下限；
- HTML 双语段落数与 PDF 正文块之比不得低于 0.45，且正式全文版本应尽可能接近经过合并后的自然段总数；
- 核心英文相对完整来源文本的覆盖率不得低于 0.45；
- 任何参考文献、表格碎片或截断段落进入正文即失败。

0.45 仅用于立即阻断明显退化版本，不代表达到全文阅读器的最终质量标准。

### 2. 基线功能等价门禁

对选定金标准版本逐项检查：

- 阅读模式；
- 双语段落结构；
- 目录；
- 右侧图栏；
- 图表索引；
- 图表精读；
- 阅读设置；
- 参考文献浮窗；
- 左右栏拖动；
- 批注与绘图。

新增版本不得用一套新的简化壳替换金标准功能后仍标记“通过”。

### 3. 浏览器行为门禁

浏览器测试必须从最终交付 HTML 重新模拟所有关键行为，不得复用生成器自己的布尔值。浏览器通过只证明交互可执行，不能覆盖内容完整性门禁。

## 七、批量执行

- CANVAS 金标准仅用于定义内容模式和功能合同，不能作为通用 PDF 生成能力已经成立的证据。
- 每篇论文必须独立执行：PDF 审计 → 内容清单 → 翻译与图表解释 → V0.8/V0.8.1 渲染 → 内容门禁 → 功能门禁 → 浏览器门禁。
- 当前论文失败时停止后续任务；修复必须写入公共解析器、内容生成器、渲染器或验证器。
- 禁止只修改单个 HTML 后继续批量生成。

## 八、发布报告

每篇论文的发布报告必须同时提供：

- PDF 审计 SHA256；
- 内容清单 SHA256；
- HTML SHA256；
- PDF 正文块数；
- HTML 双语自然段数；
- 英中对应数量；
- 正文覆盖率；
- 图表、图注与精读覆盖率；
- 引用与参考文献覆盖率；
- 基线功能缺失项；
- 浏览器错误和控制台错误。

只有三类门禁均通过时，报告才允许出现 `passed: true`。
